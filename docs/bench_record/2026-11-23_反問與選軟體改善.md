# 反問與選軟體改善（2026-11-22～23）

前提：學校電腦已和柏碩的環境對齊（`2026-11-22_學校電腦llamacpp對齊.md`），基準是 `cuda_school`。
全部用開發題組 `dev_scenario`（200 題）與 `dev_claude`（300 題）。逐題結果在 `experiments/model_select/reason/results/`。
**這些門檻與做法都是看這兩組題目決定的，數字偏樂觀**；真正沒看過的題目要看獨立驗證題組（`holdout`，見最後）。

## 1. 問題在哪（讀錯題的結論）
- **該問沒問**：「那個系統」「照舊」「跟去年一樣」這類句子，選軟體信心度仍 ≥0.8，系統直接猜。信心度只看「軟體符不符合」，不看「句子講清楚沒」。
- **不該問卻問**：
  - 問軟體的 39 題全是信心度 <0.8。句子其實清楚，是矛盾要求或一次要兩套拉低了信心度。
  - 問定時指令 16 題，題組的標準答案是不用問。
- **題組標準本身不一致**：
  - 矛盾要求有的標該問（D066）、有的標不用問（D120、D169）。
  - 做不到的要求同樣不一致（D088 該問、D111 不用問）。
  - 自己的程式沒給指令，C113 標該問，C160、C230 標不用問。

## 2. 和使用者定的規則（11-22）
- **該問**：沒講是哪一類軟體；自己的程式沒講語言；矛盾會改變要裝哪一套。
- **不用問**：類型清楚，只是設定矛盾或要求做不到。這些在部署單提醒，用安全的那邊。
- **定時執行沒給指令**：先放範例指令＋提醒（使用者決定）。

## 3. 做法與開關（程式預設都關，`.env.example` 有說明）
| 開關 | 作用 |
|---|---|
| `PIPELINE_CLARITY=on` | Gemini 正規化時順便判斷「有沒有講清楚要哪一類軟體」（方案 E）；沒 Gemini 時本地模型讀 Yes 機率（方案 C） |
| `PIPELINE_CLARITY_LO/HI` | 本地判斷門檻，採用 0.1／0.6 |
| `PIPELINE_TRUST_SUGGEST=1` | 講清楚、而且 Gemini 建議的軟體在知識表裡（不是執行環境），直接採用 |
| `PIPELINE_CLARITY_COMBINE=or` | Gemini 說清楚但本地很確定沒講清楚也問（實測沒有比較好，不建議開） |
| `PIPELINE_CRON_COMMAND` | `example`（預設）＝範例指令＋提醒；`ask`＝問問題卡 |

## 5. 過程中修正與發現（照實記錄）
- **Gemini 第一版判斷太嚴**：欄位叫 `software_clear`，36 題裡 16 題判成沒講清楚，但它自己都給了正確類別與建議（例如網站給 wordpress）。
  - 改成 `kind_clear`，先填類別再判斷。
  - 程式加保險：Gemini 說沒講清楚、卻建議了知識表裡的軟體，改用本地判斷。
- **本地 C 第一版的範例太像錯題**（C215、C076、C279、D200 的模式），範例換成跟題組無關的句子後重跑：
  - claude 整張全對 185→179。代表第一版約一半的進步是範例造成的。
  - 該問有問 28→29，這部分是真的。
- **本地 C 分得開 claude 組，分不開 scenario 組**：claude 該問的 38 題有 19 題機率 <0.1；scenario 該問的 43 題只有 1 題。原因是 scenario 的「該問」多是矛盾或做不到的要求，照規則本來就不用問。
- **scenario 少問到的題（D046、D057、D078、D134、D197）**：照規則屬於不用問，標成「題組與規則不一致」。
  - Gemini 真正判錯的是 **D040、D065**：自己的程式沒講語言，應該問。
- **資源下限不做**：CPU 下限 500m、記憶體 512Mi 的模擬，兩組都變差（scenario 67→63～66、claude 185→172～176）。
  - 原因：有些題目要的資源本來就少；資源給太少的題目大多還有別的欄位錯。
  - 柏碩 11-19 也得到一樣的結論。
- **剩下的錯誤**（Gemini＋採用建議）：
  - scenario：主要是 CPU 太少（46 題）、記憶體太少（31）、軟體選錯（約 30）。
  - claude：主要是軟體選錯。
  - 兩組的資源評分標準不同：scenario 大方、claude 保守。

### 用開發題組查到的流程漏洞（claude 組）
- 推理那一步選了執行環境（alpine／node／python），而 Gemini 把「一個小程式在背後默默跑」這種描述抽成啟動指令。
- Gemini 抽出來的額外欄位一律標成「使用者給的」，選軟體的步驟看到「使用者給了指令」就提早結束，「採用建議」沒有機會執行。
- 例子：C012、C110、C128、C273。用快取重跑確認過。
- 離線模擬：worker 類型照樣採用 Gemini 建議（在知識表、不是執行環境）：
  - claude 軟體變對 9、變錯 0。
  - scenario 沒有影響。
  - 定時執行（cronjob）2 對 1 錯，不建議放行。
