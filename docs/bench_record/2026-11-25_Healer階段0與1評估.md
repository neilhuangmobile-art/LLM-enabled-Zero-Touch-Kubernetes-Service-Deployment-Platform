# Healer 補強階段 0＋階段 1：開發題組評估（2026-11-25）

- 方案：`docs/healer_plan_20261120.md`（GitHub issue #2）
- 評估工具：`experiments/healer_eval/`（`faults.py` 題組、`run_eval.py` 執行與判定）
- 結果檔：`experiments/healer_eval/results/healer_old.jsonl`、`healer_new.jsonl`；第一輪（評分程式有漏洞、已作廢）在 `results/round1/`

## 結論

| | 舊版（`934600e`） | 新版（階段 0＋1） |
|---|---|---|
| 通過 | 17/22 | **22/22** |
| 該停手的題（17 題）有停手 | 12 | **17** |
| 該修好的題（5 題）有修好 | 5 | 5 |
| 自動動手的題數 | 10 | 6 |
| 修壞 | 0 | 0 |

逐題配對：只有新版對 5 題、只有舊版對 0 題，McNemar p=0.062（22 題，題數少）。

**舊版的問題都很嚴重**：
- 程式本身的錯（exit 1）：重建 Pod 24～46 次（每 30 秒一次）。
- log 印出「OOMKilled」但沒有真的記憶體不足：記憶體一路翻倍到 **128Ti**（20 次）。
- 一啟動就正常結束（exit 0）：重建 2 次。

**新版**：
- 上面幾題都停手，只通知。
- 多副本的程式錯誤照權限表重建一次，驗證失敗後停手（不再重建）。
- 該修的 5 題都修好，而且每次修完都有驗證通過（`verify=ok`）：記憶體不足調高一次、探針 port 錯改成正確 port、啟動太慢放寬等待時間、映像檔改壞退回到曾經正常的版本。

## 題組（開發題，22 題）

14 類故障＋對照組：記憶體不足 2、程式錯誤 3（含多副本）、映像檔 tag 錯（有／沒有正常版本）2、私有映像檔 1、探針 port 錯 1、啟動太慢 1、缺 ConfigMap 1、缺 Secret 1、相依服務連不上 1、權限不足 1、指令找不到 1、一啟動就結束 1、log 假 OOM 1、資源不夠 Pending 1；對照組：正常 nginx、redis、會印 HTTP 403 存取紀錄的服務、暫時性故障（第一次失敗之後正常）。

判定（全部由 K8s 狀態自動判定）：
- 停手題：沒有自動改設定（多副本程式錯誤允許重建 1 次，照方案權限表）；可修好的對照組結束時還要健康。
- 可修題：結束時健康，而且穩定 120 秒。
- 「健康」＝更新完成、全部可用、沒有卡住的舊 Pod、沒有不可用的副本。

## 評估過程發現並修正的問題

1. **新版 bug：更新卡住時把壞映像檔記成「曾經正常」**。映像檔改壞時舊 Pod 還在跑，available／updated 看起來都滿了。修正：健康判斷加上「沒有多出來的舊 Pod、沒有不可用的副本」（`guard.deployment_healthy`），驗證也用同一個判斷。
2. **新版：去重 key 用 K8s reason**，崩潰的容器在 Error 和 CrashLoopBackOff 之間切換，被當成兩個問題，多副本重建了 2 次。修正：歸成同一類（`guard.problem_class`）。
3. **評分程式漏洞**：同第 1 點，卡住的更新被判成健康。修正後兩版都重跑；第一輪結果作廢（放在 `results/round1/`）。
4. **網站上的副作用**：有 bug 的版本在網站跑了約 25 分鐘，在 `local-path-storage`（系統儲存元件）和 8 個休眠喚醒器的 Deployment 上寫了「曾經正常的映像檔」標記（只是 metadata，不會重建、不影響運作）。已全部移除；`local-path-storage` 加進預設排除，記錄時跳過喚醒器。確認沒有服務被記錯映像檔。

## 限制

- **題目是調整 Healer 的人出的**（開發題組），不能當最終成績。方案規定盲測題要由不調整 Healer 的人出，版本凍結後只跑一次。
- 22 題、每版只跑一次，p=0.062，還不能說統計上顯著。
- 評估沒有呼叫診斷模型（`--llm` 才會），動作由規則決定；兩版設定相同。
- **偵測範圍沒變**：資源不夠 Pending 兩版都偵測不到（階段 2 的工作）。
- **診斷代碼仍有錯**：缺 ConfigMap／Secret、指令找不到被診斷成 `fix_image`（規則 `image.*not found` 會跨事件文字比中），兩版相同。新版因為沒有「曾經正常的映像檔」紀錄而不動手，所以沒造成傷害，但診斷文字是錯的，之後要修。
- 客戶叢集的驗證與退回這次沒做（要等 Flux 同步＋回報器），只共用了記憶體上限與結構化證據。

## 重跑方式

```bash
# 網站要跑新版（新版的背景 Healer 會跳過 healer-eval-*；舊版不會）
python experiments/healer_eval/run_eval.py --tag new --run n3
git worktree add ../zt-healer-old 934600e
python experiments/healer_eval/run_eval.py --tag old --run o3 --code-root ../zt-healer-old
python experiments/healer_eval/run_eval.py --compare old new
```
每版約 8 分鐘（22 題同時跑，各自的 namespace，結束自動刪除）。
