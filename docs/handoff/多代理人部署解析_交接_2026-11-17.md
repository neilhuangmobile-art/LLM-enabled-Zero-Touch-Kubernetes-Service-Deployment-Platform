## 2. 整體流程

```
使用者一句話
  │
  ▼
① 正規化 normalize.py ──── Gemini 優先，失敗改本地模型（同一份 NORMALIZE_SYSTEM）
  │   只寫使用者講過的；值在原句找不到根據就丟掉
  ▼
② 意圖檢查（缺漏）intent_check.py ── 本地模型比對原句與 JSON，最多 3 輪 → 問
  ▼
③ 空缺檢查 gap_check.run
  │   ├─ 推理代理 reasoner.fill_gaps（只送原句），最多 3 次
  │   ├─ _verify_image：簡稱補全名；推理代理捏造、不在知識表的映像檔 → 清空
  │   ├─ _select_software：本地模型在「推理代理的選擇＋RAG 候選」裡挑
  │   ├─ _table_and_defaults：port／資源／名稱／服務類型查表或給預設值
  │   └─ _ask_image：還是不知道軟體 → 問題卡，選項是 RAG 候選
  ▼
④ 意圖檢查（符合度）verify.run ── 只有沒有待答問題時才跑；目前只檢查排程
  ▼
⑤ 額外欄位對應 reasoner.apply_extras ── 固定規則，把密碼、保存資料、指令、排程…寫進部署設定
  ▼
⑥ 格式檢查 format_check.run ── 規則修 → 模型修 → 重新檢查，最多 3 輪 → 問
  ▼
有問題卡？── 有 → 網站顯示問題卡 → 使用者回答 → runner.resume（從 ③ 接著跑，不重新正規化）
  │
  ▼ 沒有
runner.to_payload → 網站原本的 _prepare_deploy（補全、情境、負荷檢查、三個審查代理、dry-run）
  ▼
可修改的部署單 → 使用者按部署
```

串接順序寫在 `agents/pipeline/runner.py` 的 `run`、`resume`、`_finish`。

## 3. 每一塊的設定

### 3.1 中間 JSON（`schema.py`）

- 基礎欄位 6 個：`image`、`app_name`、`replicas`、`port`、`memory`、`cpu`，每個存成 `{value, source, evidence}`。
- **來源等級**：`user`（3）＞ `inferred`（2）＞ `default`（1）。後面的步驟不能蓋掉等級比自己高的值，統一由 `set_field`／`set_choice` 把關。
- `workload`：`service`／`worker`／`cronjob`；`expose`：`public`／`internal`／`none`。
- 其他欄位：
  - `extras`：額外欄位，每筆有 kind、desc、value、evidence、source、status、note。status 是 pending／applied／unsupported／dropped。
  - `manifest`：對應出來的部署設定（env、secret_keys、volumes、command、extra_ports、schedule）。
  - `questions`：問題卡。有推薦值時最後一定附「幫我決定」（`__auto__`）。
  - `notices`：要明白告訴使用者的事。
  - `rejected`：格式不合格被丟掉的值，給 ⑥ 修。
  - `verified`：④ 改過的值。
  - `trace`：每一步的耗時與說明。
  - `attempts`：各步驟跑了幾輪。
- 格式規則（`clean_value`）：
  - 名稱：小寫英數與 `-`，42 字內
  - 副本數：1～20（`MAX_REPLICAS`）
  - port：1～65535
  - 記憶體：`數字Mi`／`數字Gi`
  - CPU：`500m` 或 `1`、`0.5`

### 3.2 ① 正規化（`normalize.py`、`prompts.NORMALIZE_SYSTEM`）

- 先用 Gemini（`llm.gemini_llm`，走 `core/gemini_client._generate`，有 key 輪換）。沒有 key、回錯誤、輸出不是 JSON 時，改用本地模型跑同一份提示詞。實際用了哪一個記在 `spec["backend"]["normalize"]`。
- **根據檢查（`grounded`）**：模型寫進基礎欄位的值要在原句找得到才算 `user`，找不到就丟掉並記在 trace。原因是 11-11 實測 Gemini 會把軟體名稱抄進 app_name。數字會比對阿拉伯數字、中文數字與英文數字。
- **額外欄位種類**：env、secret、storage、command、schedule、no_expose、extra_port、other。
- **evidence 檢查**：額外欄位的 evidence 一定要是原句裡的字。
- **明確字眼檢查（`_CUE`）**：「不對外」「定時」這兩種要在 evidence 裡看到明確字眼才採用。「連不上／掛掉」這種雙重否定不算不對外。S40 實測過「QR code 給客人看」被當成不對外、「為期三天」被當成定時執行，才加了這條。

### 3.3 ② 意圖檢查：缺漏（`intent_check.py`、`INTENT_SYSTEM`）

- 本地模型拿原句和目前的 JSON 比，列出漏掉的要求，經過 `add_extra` 同一套 evidence 檢查才加進去。
- 某一輪沒有新的漏項就結束；最多 3 輪（`MAX_ROUNDS = 3`）。第 3 輪還有新東西，就做成問題卡：「照我說的做／不用了」。

### 3.4 ③ 空缺檢查與推理代理（`gap_check.py`、`reasoner.fill_gaps`、`REASON_SYSTEM`）

- **推理代理**：
  - 6 個基礎欄位有空的、或還不知道服務類型和要不要對外，才呼叫推理代理，最多 3 次。
  - 補不出新東西、或模型自己說要問使用者，就不再重試。
  - **推理代理只收原句**。11-17 實測附上「已決定的欄位」後，S38、S39 就不提問、直接猜軟體。使用者講過的欄位靠來源等級保護，不靠提示詞。
  - 推理代理也會推「系統建議」的額外欄位，例如部落格要保存資料；部署單上標成系統建議。
- **映像檔查證（`_verify_image`）**：
  - 簡稱補成完整名稱，例如 grafana → grafana/grafana，並告知使用者。
  - 推理代理推的映像檔不在知識表裡就清空，改問。實測抓到的捏造名稱有 redis/redis、mikepenz/mediawiki。
- **選軟體（`_select_software`、`SELECT_SYSTEM`）**：
  - 只處理推理代理推的映像檔；使用者講的不動。
  - 資料庫（postgres、mysql、mariadb、mongo、redis、memcached）與程式執行環境（python、node…）不換。
  - 只能從清單裡選，選不出來就維持原本的。
  - 實測每題多 2～3.5 秒。
- **查表與預設值（`_table_and_defaults`、`defaults.py`）**：
  - port：查表為準；使用者講的不蓋。查不到給 80，背景程式與定時執行改成不對外。
  - 副本數：預設 1。
  - 名稱：預設用映像檔名稱。
  - 記憶體、CPU：`cost_agent.recommended_resources` 依映像檔類型給。
  - 服務類型預設 service、對外預設 public；背景程式與定時執行一律不對外。
- **問軟體（`_ask_image`）**：問題卡附 RAG 候選。推理代理自己推薦、而且在知識表裡的排第一。

### 3.5 選軟體的 RAG（`software_rag.py`、`rag/software_catalog.json`）

- 知識表 331 筆：
  - Docker 官方映像檔 141 筆
  - 廠商映像檔 6 筆
  - LinuxServer.io 184 筆，附官方 port 與資料夾
- 每筆附公開說明與來源。重抓用 `scripts/build_software_catalog.py`（來源是 docker-library GitHub、Docker Hub、LinuxServer API）。
- 查法：用**原句**做 BGE-M3 向量取前 25 筆，再用 bge-reranker-v2-m3（CPU）重排取前 4 筆。向量模型載不起來就不給候選，只做查證；重排模型載不起來就用向量的排序。
- `defaults.listen_port`／`data_path` 先查知識表，再查內建表。例如 linuxserver/nextcloud 的 port 是 443。

### 3.6 ④ 意圖檢查：符合度（`verify.py`、`VERIFY_SYSTEM`）

- 找「系統填的值和使用者講的矛盾」。只檢查來源是 inferred／default 的值，使用者講的不檢查。
- **`CHECK_FIELDS = ("schedule",)`**，是使用者 11-17 決定的。沒有排程的句子不會呼叫模型。
- 模型回報的 evidence 要是原句的字，欄位要在清單內，才採用。
- 有合法建議值就直接換，部署單寫「原本 X → 改成 Y」；沒有就清空交回 ③ 重推。重推出一樣的值，就改問使用者。
- 最多 3 輪。**防來回改**：同一欄位被要求改回原值，就恢復原值、不問。
- 問題卡選「維持」會記進 `verify_skip`，之後不再檢查那一項。
- 要恢復檢查其他欄位，把欄位加回 `CHECK_FIELDS` 即可；可用的欄位見 `FIELDS`。

### 3.7 ⑤ 額外欄位對應（`reasoner.apply_extras`，固定規則）

| 種類 | 怎麼對應 | 對應不到時 |
|---|---|---|
| secret（密碼） | 依資料庫映像檔寫進對應的環境變數，並標成 Secret | 標成不支援，請使用者在部署單自己填 |
| storage（保存資料） | 掛 PVC 到查表得到的資料夾；預設 1Gi，上限 5Gi | 使用者自己講超過 5GB → 問「先用 5GB／先不部署」，不自動調低 |
| command（指令） | 清單照用；字串改成 `["sh","-c",字串]` | 看不出指令 → 不支援 |
| schedule（排程） | 合法、而且間隔至少 5 分鐘 → 服務類型改成 cronjob、不對外 | 看不懂 → 不支援；太頻繁 → 交給 ⑥ 問 |
| no_expose | 改成不對外 | — |
| extra_port（管理網頁） | 有管理網頁的軟體換成 management 版映像檔，並開管理 port | 不知道 port → 不支援 |
| env | 名稱合法就寫入，最多 20 個 | 不支援 |
| other | — | 一律標成不支援並告知 |

- 不支援的項目都會寫進 notices，網站上收合顯示，**不會默默丟掉**。
- **定時執行沒有指令**：映像檔是程式執行環境、或還沒決定映像檔時，問「每次要跑什麼指令？」，沒有「幫我決定」。

### 3.8 ⑥ 格式檢查與修正（`format_check.py`、`FORMAT_FIX_SYSTEM`）

- 服務名稱不是字母開頭，就在前面加 `app-`（網站還會建 `<名稱>-svc` 的 Service，名稱規則比較嚴）。
- 處理 `rejected` 裡的值（最多 3 輪）：
  1. 固定規則（只在第 1 輪用）：
     - 記憶體：`0.5Gi` → `512Mi`、`1.5GB` → `1536Mi`；沒寫單位不猜
     - CPU：`0.5` → `500m`、`500 millicores` → `500m`
     - port：`8080/tcp` → `8080`
     - 映像檔：`nginx 1.25` → `nginx:1.25`
  2. 規則修不好，問本地模型；提示詞規定只能改格式、不能改數量或意思。
  3. 修完一律重新過 `clean_value`。
  4. 3 輪還不行，問題卡請使用者重填。
- 修過的值記在 `format_fixed`，部署單上寫「X 的寫法不對，已經改成 Y」。
- **排程間隔小於 5 分鐘**：問「改成每 5 分鐘／先不部署」，沒有「幫我決定」，因為超過上限不替使用者決定。

### 3.9 問題卡與接續（`runner.resume`）

- 回答會從 ③ 接著跑，不重新正規化，所以使用者講過的欄位不會被蓋掉。
- `__auto__`（幫我決定）等於選推薦值。`cancel` 會取消部署。
- 各種問題的處理：

| 問題 | 回答後的處理 |
|---|---|
| `image` | 寫進映像檔，來源記成 user |
| `storage_size` | 改保存空間大小 |
| `verify:*` | 交給 `verify.resume_answer` |
| `format:*`、`schedule_interval` | 交給 `format_check.resume_answer` |
| `cron_command` | 當成使用者講的指令 |
| `extra:*` | 選「不用了」就把那一項標成丟棄 |
| 其他自由回答 | 附在原句後面，讓推理代理接著用 |

- 先前標成不支援的額外欄位（排程除外），會用新資訊再試一次。

### 3.10 本地模型伺服器（`core/pipeline_model_server.py`）

- 模型：Qwen3.5-4B，4-bit（nf4），只聽 `127.0.0.1:8766`。
- 要用 `C:\zt-k8s\.venv-qwen35` 執行，因為需要 transformers 5.x，專案 venv 是 4.57.6。執行時要設 `HF_HUB_OFFLINE=1`。
- 一次只跑一個生成；啟動時先做一次暖機，第一次呼叫要編譯約 48 秒。
- API：
  - `GET /health` → `loaded`、`vram_gb`
  - `POST /generate`，送 system、user、max_new_tokens
- 呼叫端（`llm.local_llm`）預設逾時 60 秒，可用 `PIPELINE_MODEL_TIMEOUT` 調整；網址可用 `PIPELINE_MODEL_URL` 改。
- 8765 的舊模型伺服器（3B＋1.5B）照舊在跑，開關關掉或退回時才會用到。
- 顯存：上線後約 13.7／16.3GB；8766 本身約 3.11GB。

## 4. 定時執行（CronJob）

### 4.1 安全上限（使用者 11-17 決定）

- 間隔最短 5 分鐘（`cron.MIN_INTERVAL_MINUTES`）
- 每次最多跑 1 小時（`activeDeadlineSeconds: 3600`）
- 上一次沒跑完不開新的（`concurrencyPolicy: Forbid`）
- 失敗重試 2 次（`backoffLimit: 2`）
- 時區 `Asia/Taipei`

### 4.2 YAML（`gitops/manifest_writer.build_cronjob_doc`）

- **唯一來源**：Git 紀錄、實際部署、審查、dry-run 都用同一個函式。
- 其他設定：
  - `ttlSecondsAfterFinished: 86400`
  - 成功、失敗紀錄各保留 3 筆
  - `startingDeadlineSeconds: 300`
  - `restartPolicy: OnFailure`
- 不建 Service、不加健康檢查、不開 port；Pod 標籤 `app=<名稱>`。
- 密碼走 Secret，不寫進 YAML。檔名是 `cronjob.yaml`。

### 4.3 網站（`web_demo.py`）

- **API**（都要登入，只能動自己 namespace 的，會寫事件紀錄）：
  - `GET /api/cronjobs`：排程（附中文說明）、是否暫停、上次結果、下次執行時間
  - `POST /api/cronjobs/<name>/run`：立刻跑一次
  - `POST /api/cronjobs/<name>/suspend`：暫停／恢復
- **刪除**：`k8s_delete_cronjob` 刪 CronJob、它的 Job、Secret，以及從 volume 讀出來的 PVC。不是用名稱前綴猜。
- **不適用的操作**：擴縮、更新、回復上一版遇到定時執行，回中文說明（`_CRON_NA`）。
- **`_sanitize_deploy_payload`**：檢查排程格式與間隔，副本數固定 1、不對外。
- **前端**：
  - 部署單用排程欄位取代 port
  - 完成卡有「立刻跑一次」
  - 「我的服務」新增定時執行區塊
- **健康判定**：跑完的 Pod（Succeeded）算正常。
- **Healer**：Job 產生的 Pod 只回報、不自動修（`healer/pod_watcher.py`、`_real_heal_pod`）。

### 4.4 順便修的安全問題（`docs/security_review.md` 第 65 節）

改之前，`guardian/yaml_validator.py` 和三個審查代理**完全看不到 CronJob 裡的容器**：特權模式、映像檔黑名單都不會檢查。

- 新增 `agents/k8s_shape.pod_template_spec` 統一取 Pod 設定，三個代理改用它。
- 成本代理：依「每月次數 × 每次最多 1 小時」估上限，並寫明是上限。
- 效能代理：對 CronJob 不提高可用、HPA 這類建議。
