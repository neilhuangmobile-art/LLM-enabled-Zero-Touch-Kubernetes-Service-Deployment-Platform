# RAG 目錄擴充與檢索改法對照（2026-11-15）

原始資料：`ablation.jsonl`（每組設定的摘要與檢定）、`ablation_rows.jsonl`（每題結果）、
`ablation_catalog36.jsonl`（第一輪，只有 36 種目錄）。程式：`rag/tune_fields.py`。

## 方法

- 開發集 200 題依題號雜湊固定分成調整 140 題、驗證 60 題；只算不需反問的題目（調整 105、驗證 52）。
- 每組設定與基準逐題配對，做精確 McNemar 檢定。
- 採用規則寫死在程式裡：調整組第 1 名或前 3 名命中提高且 p < 0.05、驗證組不退步、另一指標沒有顯著變差。
- 類別正確率（第 1 名與標準答案同類別）一律用同一份類別對照，避免目錄不同造成比較偏差。

## 查證

- 獨立索引分層在差距設為極大值時，105 題的第 1 名與前 3 名與 36 種版本逐題完全相同（程式正確性檢查）。
- 「人工指定映像檔的 8 種軟體」（看過開發集缺口才加的）目前不在 278 種目錄中，沒有影響任何分數。

## 根本原因

105 題中有 94 題，擴充目錄最像的條目向量分數高於人工目錄最佳條目（中位數高 0.056），但正確答案多在人工目錄。
擴充目錄的描述是 Gemini 依英文簡介寫的短句，開發集也是 Gemini 寫的，兩者寫法相近，分數被墊高；
人工目錄的文件格式不同。不同寫法的文件分數無法直接比較，所以調整排序規則（加權、分層、先判斷類別）都救不回來。

## 下一步（尚未驗證）

1. 擴充目錄的描述改成與人工目錄相同的格式與寫法，並要求寫出與同類軟體的差異；重寫後重跑本實驗。
2. 用不是 Gemini 產生的題目（例如人工寫的少量題目、盲測集）確認寫法風格造成的偏差有多大。
