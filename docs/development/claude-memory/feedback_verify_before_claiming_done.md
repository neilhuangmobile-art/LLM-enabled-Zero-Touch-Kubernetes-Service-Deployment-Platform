使用者習慣在我回報「做完了」之後，用一句簡短的追問去驗證（例如「你那些測試紀錄有記錄下來嗎」
「這個修好了嗎還是沒完全修好」）。這些追問**不是**單純確認，往往是在檢查我有沒有真的做到、
還是只是講得好聽。

**Why：** 這次 session 至少兩次被這種追問挖出真正的落差：
1. 我說「prompt injection 修好了」，使用者追問「牆薄的問題除了鎖門還有沒有更徹底的方法」，
   逼我承認黑名單規則只是繞開問題、不是解決問題，最後才做出輸出端事實核對這個真正更根本的方案。
2. 我說 6 個 commit 都測試過、沒問題，使用者問「測試紀錄有記錄下來嗎」，逼我去查才發現 11 個
   commit 從沒真的 push 上 GitHub、CI 從來沒有真正執行過一次——push 上去後 CI 第一次真的跑
   就直接失敗（`@pytest.mark.integration` 標記擋不住 collection 階段的 import 錯誤）。

兩次都是「我以為驗證過了」跟「真正驗證過」之間有落差，只有在使用者追問、我被迫真的去查
（而不是憑印象回答）時才會發現。

**How to apply：**
- 使用者問「有沒有記錄下來」「真的驗證過嗎」「這樣就夠了嗎」這類簡短問句時，預設當作
  「請你現在真的去確認一次，不要只憑之前做過的印象回答」，而不是當作單純的閒聊確認。
- 回答前，如果宣稱某件事「已完成/已驗證」但其實沒有在這次對話裡實際查證過當下狀態
  （例如 CI 有沒有真的跑過、檔案有沒有真的存在、遠端有沒有真的同步），要先去查，
  不能只根據記憶或之前的操作結果回答。
- 這個使用者對「宣稱 vs 實際」的落差特別敏感（這也是 `docs/security_review.md` 好幾條
  記錄的核心主題），回答時主動點出「我剛才驗證過，結果是 XXX」比「應該沒問題」更符合
  使用者的期待。
