# 常見 Pod 狀態與健康檢查：原因、關鍵概念、怎麼修

這份文件給新手看。每一節都照同樣的順序寫：是什麼、為什麼會發生、關鍵概念、怎麼修。

## OOMKilled：記憶體不夠被系統砍掉

**是什麼**：容器用的記憶體超過了它的記憶體上限（memory limit），系統把它強制結束（OOM 是 Out Of Memory，記憶體不足）。

**為什麼會發生**：每個容器都設有記憶體上限（limits.memory）。程式需要的記憶體比上限多，例如資料量變大、同時連線的人變多、程式有記憶體洩漏，就會超過上限被砍掉，接著被重新啟動。

**關鍵概念**：
- 記憶體上限（limit）是容器最多能用多少；記憶體請求（request）是保證分給它多少。
- 被砍掉是因為超過「上限」，不是整台電腦的記憶體用完。
- 一直被砍掉、一直重啟，最後會變成 CrashLoopBackOff。

**怎麼修**：
1. 把記憶體上限調高，例如從 128Mi 調成 256Mi。在 ZeroTouch 可以直接說「把 xxx 的記憶體調成 256Mi」，Healer 偵測到 OOMKilled 也會自動調高。
2. 如果調高之後還是一直增加，可能是程式有記憶體洩漏，要檢查程式本身。

## ImagePullBackOff／ErrImagePull：拉不到映像檔

**是什麼**：K8s 要啟動容器前，必須先從映像檔倉庫（例如 Docker Hub）拉取（pull，也就是下載）映像檔。拉取失敗就會出現 ErrImagePull，重試幾次之後變成 ImagePullBackOff（等一段時間再重試）。

**為什麼會發生**：
- 映像檔名稱或版本打錯，例如 `nginx:1.99` 這個版本不存在。
- 映像檔是私人的，沒有登入權限。
- 網路連不到映像檔倉庫，或下載次數被限制。

**關鍵概念**：
- 映像檔（image）是程式打包好的安裝檔，容器是用映像檔跑起來的。
- 這個錯誤發生在「拉取映像檔」的階段，程式根本還沒開始執行，所以看程式日誌找不到原因。

**怎麼修**：
1. 確認映像檔名稱和版本正確（到 Docker Hub 搜尋看看有沒有這個版本）。
2. 換成正確的版本，在 ZeroTouch 可以說「把 xxx 的映像檔換成 nginx:1.27」。Healer 偵測到版本不存在時，也會自動換回上一個能用的版本。
3. 私人映像檔要先設定拉取用的帳號密碼（imagePullSecrets）。

## 健康檢查（probe）：readiness 和 liveness 的差別

**是什麼**：K8s 會定期檢查容器有沒有正常運作，這個檢查叫探針（probe）。

**兩種探針的差別**：
- **readiness probe（就緒檢查）**：判斷容器「能不能接收流量」。沒通過時，K8s 不會把使用者的請求（流量）送給它，但**不會重啟**它。適合用在程式啟動中、暫時忙不過來的情況。
- **liveness probe（存活檢查）**：判斷容器「是不是卡死了」。沒通過時，K8s 會**重新啟動**這個容器。
- 另外還有 startup probe（啟動檢查），給啟動很慢的程式用，啟動完成之前先不做另外兩種檢查。

**常見問題**：
- 探針檢查的 port 設錯（例如程式聽 80，探針卻檢查 8081），會一直失敗：readiness 失敗就永遠收不到流量，liveness 失敗就一直被重啟。
- 程式啟動比較慢，探針太早開始檢查，還沒啟動完就被判定失敗。

**怎麼修**：
1. 確認探針檢查的 port、路徑跟程式實際監聽的一致。ZeroTouch 的 Healer 遇到探針 port 跟容器實際監聽的 port 不一樣時，會自動改成正確的 port。
2. 啟動慢的程式，把開始檢查前的等待時間（initialDelaySeconds）加長，或加上 startup probe。
